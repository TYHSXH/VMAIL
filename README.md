# VMAIL 理论力学实验台

[简体中文](README.md) | [English](README_EN.md)

VMAIL 是一个在学生电脑本地运行的可交互 MuJoCo 实验台。学生可以让 AI coding 工具在 `tasks/` 中创建学习任务，然后在网页里加载模型、修改参数、拖动物体、调整关节与执行器、观察运动数据，并进行批量计算和保存。

浏览器使用官方 `@mujoco/mujoco` WebAssembly 运行物理仿真，Three.js/WebGL 显示三维场景。Python 后端负责读取任务、验证配置，以及执行需要保存完整数据的批量实验。

## 学生首次使用

### 方式一：一键配置和启动（推荐）

1. 安装 64 位 Python 3.11 或更新版本。安装时勾选“Add Python to PATH”。
2. 解压整个 VMAIL 文件夹，保持内部目录结构不变。
3. 保持联网，双击 `start.bat`。
4. 第一次运行时，脚本会自动创建项目专用的 `.venv`，并安装 `requirements.txt` 中的 FastAPI、Python MuJoCo 等依赖。
5. 安装完成后服务会在 `http://127.0.0.1:8000` 启动，准备就绪后自动打开浏览器。以后再次双击 `start.bat` 不会重复安装，除非依赖缺失或 MuJoCo 版本不匹配。

也可以先双击 `setup.bat` 只完成环境配置，再双击 `start.bat` 启动。

网页所需的 MuJoCo WASM 和前端代码已经构建在 `app/` 中，学生不需要安装 Node.js，也不需要单独安装网页版 MuJoCo。

### 方式二：使用已有 Conda 环境

在 Anaconda Prompt 中进入项目目录，激活希望使用的环境，然后执行：

```powershell
python -m pip install -r requirements.txt
.\start-current-python.bat
```

这种方式不会使用项目的 `.venv`。Conda 环境中必须能导入 `fastapi`、`uvicorn`、`yaml`、`numpy` 和 `mujoco`。

## 模型预览（拖入 XML）

任务的“参数”页同时提供**关节姿态**与质量、刚度等模型参数：关节可用滑块或数值调整，转动关节支持度／弧度切换，滑动关节以米显示，并遵守模型限位。调整关节会暂停仿真且不记录调整过程，点击开始后从调整后的姿态运行；“恢复姿态”回到任务初始姿态。模型参数修改后需先应用，再调整关节。

任务和模型预览都会自动列出 XML 中的刚体转动、滑动关节；没有转角限位的转动关节提供 0–360°（0–2π rad）设置，不受旧任务 `controls.joints` 列表影响。闭环机构会同步调整其他关节以保持连接，无法满足约束的数值会提示并恢复原姿态。柔性部件的内部自由度不作为关节控件显示。

模型预览右侧也有相同的关节面板，工具栏“关节”按钮可收起或展开。自由基座和球关节不作为单个数值关节展示，内部机构约束仍由任务专用联动配置处理。

柔性部件对应的顶点／节点自由度不提供关节滑块，避免手动改动导致形变或约束异常；同一模型内其他刚性机构的可调关节仍可使用。

点击网页顶部的“模型预览”，或直接把一个 `.xml` 文件拖入网页，即可打开独立预览。可旋转、平移、缩放视角，切换“拖动物体”调整姿态，也可重置模型。点击“运行仿真／暂停仿真”运行 MuJoCo 物理仿真，没有时长限制，不采集曲线或保存实验结果。拖动物体时暂停播放，松开后可继续运行。点击“退出预览”或按 Esc 返回原任务界面，原任务保持暂停，已有参数和数据保留。预览不会创建任务或修改原始模型。

**模型库模型：**可在预览顶部“从模型库选择”中选择模型及入口（优先选择 scene.xml），后台会展开 include 并读取配套 STL、OBJ、纹理等文件，再交给浏览器引擎。也可只拖入库内原始 XML，系统根据文件名和内容识别对应目录并自动补齐依赖；同名同内容无法唯一确定时，请用下拉框指定模型。请保留完整的 `model_library/` 目录。模型和 scene 分开存放不影响加载。

**库外或修改过的 XML：**每次仍只导入一个 XML；没有外部文件依赖的模型可直接预览。浏览器不能通过单个 XML 获取读取其所在文件夹的权限，所以库外 XML 缺少 include、网格或纹理时会列出具体文件。这类模型可按任务包流程整组放入任务目录。拖入的 XML 会发给本机 VMAIL 后台匹配和解析，不写入磁盘。STL 网格作为二进制资源传递，不当作文本读取；独立 STL 文件不是 MuJoCo 模型，入口仍需 XML。

预览不附带训练策略或平衡控制器，机器人可能在重力下倾倒；静态固定机构也可能保持不动，具体运动由模型约束、重力和原有执行器决定。

预览加载和重置时，优先使用模型提供的 `home` 等初始关键帧；没有匹配名称时使用第一个关键帧，没有关键帧则使用模型默认状态。学习任务仍以任务配置指定的初始状态为准。柔性体支持一维绳线、二维表面、三维柔性表面及蒙皮的动态绘制，顶点随 MuJoCo 状态更新。

库内资源使用二进制传输；暂停且视角不变时不重复绘制，预览时后台任务视窗停止绘制。复杂模型会降低阴影和像素密度，并限制每帧连续物理计算的时间预算，不放大模型原有时间步长：计算量过大时仿真会慢于现实时间，仍需按学生电脑性能选用模型。

任务模型的引用资源上限已提高为 **128 MiB（134,217,728 字节）**，计入 XML 引用的网格、纹理等文件，不计 XML 文本或未引用文件。独立预览的单个 XML 文本最多 **16 MiB**。这些是本项目的加载限制，模型复杂度仍会影响浏览器运行速度。

## 常见问题

- 首次安装失败：检查网络，关闭脚本窗口后重新运行 `setup.bat`。
- 提示找不到 Python：重新安装 Python，并勾选加入 PATH；也可以使用已配置好的 Conda 环境。
- 网页打不开：确认启动窗口没有报错，并访问 `http://127.0.0.1:8000`。
- 提示端口占用：如果 VMAIL 已在运行，直接访问上述地址；否则关闭占用 8000 端口的程序后重试。
- 右键拖动出现蓝线或触发后退/关闭：通常是浏览器或扩展的鼠标手势拦截。可使用视窗的“平移”按钮后左键拖动，或按住 Shift 用左键平移。
- 页面没有新任务：确认任务已经加入 `tasks/manifest.yaml`，然后点击网页左侧“刷新学习任务”。
- 修改了前端源码：教师或开发者需运行 `npm install` 和 `npm run build`；普通学生不需要。

## 学习任务工作流

需要工程与机器人选题素材时，可先阅读 [MuJoCo 模型资料库](model_library/README.md)。其中按类别收录了原始 XML、配套网格与纹理、来源与许可证；创建任务时可整组复制，并留意插件和资源大小提示。这些资料尚未改造成可直接加载的学习任务。

1. 学生向 AI coding 描述真实对象、研究变量和希望观察的结果。
2. AI 阅读 `tasks/AGENTS.md` 和 `docs/task-package-spec.md`。
3. AI 在 `tasks/<task_id>/` 中创建或修改任务，并登记到 `tasks/manifest.yaml`。
4. AI 运行任务校验。
5. 学生在网页中刷新任务，修改参数并开展实验。
6. 任务要求变化时，学生回到 AI coding 更新同一个任务文件夹，再在网页中重新加载。

`tasks/manifest.yaml` 是全部任务共用的“目录索引”，因此必须位于 `tasks/` 根目录，而不是任何一个示例任务中。示例任务自己的内容位于 `tasks/example_mass_spring/`。

## 实验台操作

- 三维视窗：左键旋转、Shift＋左键平移、滚轮缩放；“平移”模式下左键直接平移。每次载入任务均恢复该任务默认视角。
- 任务栏：点击标题旁的铅笔按钮修改标题，“保存”会同步到 `tasks/manifest.yaml` 与对应任务的 `task.yaml`。右侧首先显示任务说明。
- 仿真：任务载入后保持静止，点击开始才运行；支持暂停、继续、单步、重置、显示接触点和复位视角。
- 拖动是独立的姿态调整阶段：暂停正式实验，临时停用执行器，不计时、不采集数据；松手后清除拖动产生的速度并保持暂停。点击“开始仿真”才从调整后的姿态、t=0 开始实时实验。“重置”仍恢复任务原始初始状态。
- 参数页：修改质量、刚度、阻尼、初始状态或 AI 暴露的其他 MJCF 参数；应用后重新编译模型。
- 控制页：直接设置一维滑动/转动关节位置；对模型中的 actuator 实时写入 MuJoCo `ctrl`。控制值按任务和 actuator 名称记忆，应用参数重载、重置或重新开始时不会归零。
- 数据页：曲线按物理量和单位分图纵向排列；每张图有坐标轴、单位、显示开关和数值，悬停可联动读取历史时刻，Shift＋滚轮缩放时间轴，双击恢复全程；面板变宽时图表同步变宽。开始运行时自动进入数据页。
- 一个图中的曲线全部取消勾选时，图表收起，仅保留各物理量名称、值和勾选框；重新勾选会展开。任务说明会显示为排版后的正文，并支持 LaTeX 数学公式，字体和渲染代码均随 app 打包，不依赖学生联网加载。
- “导出当前数据”下载当前曲线缓存的 CSV；“批量计算并保存”暂停实时实验，从初始状态重新运行 Python 批量实验，并继承当前固定控制值，不继承拖拽历史或变动控制过程。批量结果与实时数据保持隔离，重新开始实时实验时清空批量曲线。
- 批量计算显示进度并可取消；单次最多 200000 步、2000000 个观测数值、3600 秒仿真时长，步长至少为 0.00001 秒。计算运行超过 60 秒会终止。已保存实验可在数据页下载。
- 点观测：任务可通过具名 MuJoCo `site` 记录刚体固定点的位置、速度和加速度，网页与 Python 结果采用同一字段和 SI 单位。
- 布局：桌面端可拖动左右侧栏边缘调整宽度，设置会保存在当前浏览器中。

“仿真时长”同时控制网页实时仿真和 Python 批量实验；网页到达设定时长后会自动暂停。“时间步长”会在应用参数重载模型时作用于两种计算。实时值、曲线图例和导出 CSV 均标明单位。

## 项目结构

```text
app/                    已构建的网页和 MuJoCo WASM
frontend/               网页源代码
backend/                本地 API 与 Python 批量仿真
docs/                   工作流和任务包规范
prompts/                可交给 AI coding 的提示词
tasks/
  AGENTS.md              AI 创建任务时必须遵守的规则
  manifest.yaml          全部学习任务的全局索引
  <task_id>/             每个学习任务的独立文件夹
setup.bat                首次环境配置
start.bat                自动检查环境并启动
start-current-python.bat 使用当前 Python/Conda 环境启动
```

## 教师与开发者命令

验证全部任务：

```powershell
.\.venv\Scripts\python.exe -m backend.validate_task
```

验证单个任务：

```powershell
.\.venv\Scripts\python.exe -m backend.validate_task example_mass_spring
```

修改 `frontend/` 后重新构建：

```powershell
npm install
npm run build
```

详细任务格式见 [docs/task-package-spec.md](docs/task-package-spec.md)，学生与 AI 的推荐对话起点见 [prompts/student-task-builder.md](prompts/student-task-builder.md)。
