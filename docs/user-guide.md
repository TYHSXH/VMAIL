## 课程教学路径

VMAIL 将理论力学课程组织为“知识学习 → 工程应用”两个层次，贯穿问题分析、模型构建、结果验证、参数优化和实物实践。学生通过与 AI 交流推进学习，并对假设、推导和结论进行独立核对。

### 一、知识学习

#### 1. 解题思路

与 AI 交流分析过程，明确研究对象、已知条件、约束和待求量，进行运动分析与受力分析，列出并求解方程，验证作业求解是否正确。

保留分析过程、关键假设、理论结果及核对依据，作为后续仿真的对照。

#### 2. 仿真验证

构造虚拟仿真模型，明确模型与题目条件之间的对应关系。

- 观察运动，对机构运动形成感性认识，从运动趋势、约束关系和极限工况等方面定性分析仿真结果的正确性。
- 输出数据，统一理论与仿真的单位、坐标系和初始条件，定量分析两者是否一致。
- 分析误差来源，区分建模简化、参数取值、数值积分、约束求解和数据采样等因素的影响。

形成可复现的任务包、数据曲线及理论与仿真对照记录。

#### 3. 调参优化

根据仿真分析结果，思考并设计：

- 题目参数是否符合物理规律；若存在不合理条件，记录修改理由，与 AI 交互分析并修正设计。
- 从实际需求出发，题目参数是否最优；明确设计目标、约束和评价指标，与 AI 交互分析并优化设计。

保留原始条件、优化方案及前后对比数据，使改进效果有据可查。

### 二、工程应用

#### 1. 仿真设计

探索该机构对应的实际工程对象。题目中的机构可能只是工程对象的一部分，在此基础上补充功能需求、结构、驱动和约束，设计完整的工程对象并进行仿真验证。

说明从理想化题目到工程模型增加了哪些条件，以及这些条件对结果的影响。

#### 2. 实验实践

应用工程图学知识，绘制几何模型，结合 CAD、3D 打印与装配实现机构运动。将实物运动与仿真结果对照，分析加工、装配、摩擦和间隙等因素带来的差异。

形成几何模型、制作与装配记录，以及实物验证结果。

#### 3. 前沿拓展

通过 AI 辅助学习和线上线下课程，补充机械设计、自动控制原理、电工电子技术等知识，结合机构、传感、驱动与控制，逐步完成自动化样机的设计与制作。

记录样机的功能目标、控制方案、测试过程与改进结果。

### 平台与课程实践的衔接

VMAIL 提供任务组织、交互仿真、参数调整、运动与受力观察以及实验数据导出，支撑上述阶段中的建模和验证。CAD 制图、3D 打印、实物装配及控制硬件实验需要结合外部工具和相应实验条件开展。

具体创建任务时，按[任务工作流](task-guide.md#任务创建流程)推进，使用[AI 任务创建提示词](task-guide.md#ai-提问与提示词)，并遵守[任务包规范](task-package-spec.md)。每轮设计都应保留假设、参数、结果和改进理由，便于复查与继续迭代。

## 安装与启动

Python 官方下载、安装包选择、PATH 检查与 Miniconda 专用环境命令见[项目首页的安装说明](../README.md#1-安装与启动windows)。

项目仓库：[TYHSXH/VMAIL](https://github.com/TYHSXH/VMAIL)。已安装 Git 的同学，在自己有读写权限的项目存放目录打开终端，执行：

```powershell
git clone https://github.com/TYHSXH/VMAIL.git
cd VMAIL
```

未安装 Git 时，也可从该仓库下载 ZIP 压缩包并完整解压。后续操作均在克隆或解压得到的项目文件夹中进行，保持内部目录结构不变。

1. Windows 电脑安装 **64 位 Python** ，建议使用 Python 3.12；安装时勾选加入 PATH。系统要求 Python 3.12 或更新版本，实际安装还取决于所用版本是否有匹配的依赖包。
2. 首次保持联网，在项目文件夹双击 `start.bat`；也可在上述终端执行 `.\start.bat`。程序会创建本机专用的 `.venv`，安装依赖并检查原生 MuJoCo 能否计算。
3. 浏览器会自动打开 <http://127.0.0.1:8000>。保留启动窗口；使用结束后在窗口按 Ctrl+C 停止服务。

以后仍双击 `start.bat`，环境正常时不会重新安装。学生无需安装 Node.js，也无需单独下载 MuJoCo：实时仿真在浏览器运行，批量计算使用同时安装的 Python 原生 MuJoCo。

**换电脑：** 复制项目文件，不复制 `.local`、`.venv`、`node_modules`、`.npm-cache` 和 `.git`。新电脑先安装 Python，再双击 `start.bat`。必须保留 `app`、`backend`、`docs`、`tasks`、`model_library`、`assets`、`licenses`、版权文件、`requirements.txt`、`constraints.txt` 及三个启动/安装 BAT 文件；已保存的实验结果可按需要一起复制。

如果已经使用 Conda，在目标环境安装 `requirements.txt` 后运行 `start-current-python.bat`；这种方式使用当前环境，不使用项目 `.venv`。

## 卸载与重新安装

先在启动窗口按 Ctrl+C 停止 VMAIL，再双击项目根目录的 `uninstall.bat`。脚本会删除一键安装创建的 `.venv`，一次清除其中的 Python 依赖，包括原生 MuJoCo；卸载不需要联网。

任务、实验结果、项目文件及 `.venv.backup-*` 旧环境备份会保留，系统 Python 和 Conda 环境不受影响。通过 `start-current-python.bat` 使用的外部环境不由此脚本卸载。若提示环境正在使用，请关闭相关程序后重试。

需要重新使用时，保持联网双击 `start.bat` 即可重建环境。若连项目文件也不再需要，可在备份实验结果后自行删除项目文件夹。

## 开始实验与视角操作

1. 点击左侧任务名称，先阅读右侧“任务”页。
2. 点击“开始仿真”运行动画并采集数据；可暂停、继续、单步或重置。达到设定时长后会自动暂停。
3. 左键旋转视角，Shift＋左键平移，滚轮缩放；也可切换工具栏中的“旋转”“平移”模式。“复位视角”恢复默认视角。

“拖动”模式用于调整物体起始姿态：按住物体拖动时暂停实验，不计时、不采集数据；松开后点击开始，从调整后的姿态和 t=0 运行。“重置”恢复任务原来的初始状态。

可拖动左右面板边缘调整宽度；“参数与数据”可收起或展开右侧面板。新增任务后点击左侧刷新按钮。

任务名称旁的编辑图标可修改名称，垃圾桶图标可删除整个任务。点击垃圾桶后还需要在弹窗中确认；选择“取消”或按 Esc 不会删除。确认删除会移除该任务的模型、配置及全部实验结果，不能通过网页恢复；后台计算中的任务需先等待完成或取消计算。若文件被其他程序占用而未完全清理，页面会提示残留目录。

## 用 DeepSeek 对话创建任务

网页启动时默认收起右侧参数与数据栏；需要时点击顶部“参数与数据”展开。点击顶部“我是菜鸟·AI”或右侧“AI 助手”页签，可打开“我是菜鸟，需要辅助”对话栏，描述研究对象、连接约束、已知条件、可变参数与观测结果。助手会先澄清建模条件，你可以继续补充或提问。

可用输入框下的“＋ 图片”选择题目图、机构草图或截图，也可将图片拖入网页，或在对话输入框粘贴剪贴板图片。发送前显示缩略图，可逐张移除；点击发送后图片才会随对话传给 DeepSeek，随对话保存在本机记录中。支持 PNG、JPEG、GIF、WebP，每条消息最多 4 张，每张最多 5 MB；单边最长 8192 像素。每次发送的上下文最多携带 8 张、合计 20 MB；过长时只发送近期上下文，较早图片仍在聊天记录中。图片会随多轮对话和后续任务生成继续作为上下文，可能增加 API 费用。

图片理解使用 **DeepSeek Flash**；V4 Pro 目前仅用于文字对话。如果选择了 Pro，请在“历史与连接”中切换 Flash 并保存。图片与 XML 使用统一拖放分流：纯图片打开 AI 助手，单个 XML 打开模型预览，混合拖放会提示分开导入，不会互相误读。

首次使用“历史与连接”会自动展开，填写你自己在 [DeepSeek 开放平台](https://platform.deepseek.com/api_keys) 创建的 **API Key**，选择模型并保存；这里不填写 DeepSeek 账号密码。绑定后该区域自动折叠，为对话腾出空间；切换历史记录或修改连接时再展开。可点击“测试连接”验证密钥和模型访问权限。联网调用产生的费用由该 API 账户承担，对话和任务草稿会发送给 DeepSeek。

默认只在本次 Python 服务运行中保留密钥；关闭启动窗口后需重新绑定。可勾选“在这台电脑记住密钥”，使用当前 Windows 用户的加密能力保存到项目 `.local/`，不会写入网页源码、浏览器存储或任务文件。更换电脑或 Windows 用户后重新绑定；共享电脑使用结束前点击“解除绑定”。复制或分享项目时不要携带 `.local/`，Git 已忽略该目录。

直接与 DS 对话即可。例如描述“帮我创建一个单摆任务”，也可以先讨论受力、上传题图或逐次补充条件，不需要按固定流程点按钮。条件足够时，DS 会提交任务文件，网页在后台检查并试运行，成功后自动保存到 `tasks/<task_id>/`、登记到左侧列表，并显示程序的真实结果。

先在左侧选中任务，再说“修复这个任务的报错”“调整刚才模型的约束”或“增加一个观测量”，助手就能读取当前任务并在原编号下继续修改，无需重复新建。也可以直接指定已有任务编号。新对话仍能读取选中任务。

如果文件输出不完整或模型无法运行，错误会出现在对话中，可继续让助手修正。新建不会覆盖已有编号；修改只保存改动文件，保留其他配置、资源与实验结果。修改前会备份原文件到 `.local/task-history/<task_id>/`，校验失败时保留原任务。文件被其他操作修改后需重新读取；批量计算期间暂不保存修改。生成后的“任务文件”默认折叠在输入框上方，点击向上弹出校验结果与文件内容，不挤压对话；再次点击、点击外部或按 Esc 收起。只讨论题目或概念时不会强制创建任务。

聊天不再以固定 40 条消息作为结束条件。较长时自动选择近期上下文，保留当前任务文件和修复问题，并提示有较早内容未随本次请求发送；完整聊天记录仍在页面中。较早条件可能需要重新说明。单条内容与每次请求仍有体积保护，模型本身也有有限上下文容量。

当前网页 AI 创建支持基础几何体与 `loads.yaml` 标准载荷，不接受外部网格、插件、文件引用或 Python 脚本。logo 资源由程序自动复制。复杂素材任务使用本地 AI 编程工具工作流；具体见[复杂几何体与 STL／MJCF 建模指南](task-guide.md#复杂几何体与-stlmjcf-建模)。

对话文字、图片和草稿自动保存到 `.local/assistant-history.sqlite3`，刷新页面或重启后可恢复。在“历史对话”选择旧记录；“新对话”保留旧记录；“删除此对话”确认后只删除该对话及其图片、草稿，不删除已创建任务或实验结果。关闭页面前确认显示“已保存到本机”；读写失败会提示。记录以本地明文保存，不随项目分发。恢复旧对话后，任务操作对象仍以左侧当前选择或明确指定的任务编号为准。中断的轮次标记为未完成，不会自动重发或保存任务。生成或校验期间点击“停止等待”，本轮不进入保存；进入保存阶段后会完成写入，已发出的 API 请求仍可能计费。校验通过说明文件和默认工况可以运行，不代表物理建模正确，仍需用理论、单位和极限工况核对。

## 在 VS Code 中绑定 DS API

用 VS Code 打开整个 VMAIL 文件夹，按 [DeepSeek 官方 VS Code／Copilot 集成教程](https://api-docs.deepseek.com/quick_start/agent_integrations/github_copilot/)安装其链接的 DS 扩展及配置 Copilot 账号。在命令面板（Ctrl+Shift+P）执行 **DeepSeek: Set API Key**，输入自己的 Key，再在 Copilot Chat 的模型选择器中选择 DeepSeek。网页和编辑器的密钥绑定各自独立。其他兼容插件可使用 Base URL `https://api.deepseek.com` 与 `deepseek-flash`，具体字段以插件和官方文档为准。完整步骤见[项目首页](../README.md)。

需要本地创建任务时，先让 AI 阅读 `tasks/AGENTS.md`，复杂外形再读网格建模指南；学生准备 STL，AI 辅助写 MJCF，校验通过后回网页刷新任务。

## 参数、关节与控制

- **参数与控制 · 模型与初始条件：** 修改质量、刚度等参数及仿真时长、时间步长，然后点击“应用参数”。应用后模型重新加载。
- **关节姿态：** 在同一页上方用滑块或数值调整转动、滑动关节。转角可切换度/弧度；滑动位置使用米。调整时暂停且不记录数据，“恢复姿态”返回初始状态。闭环机构会联动其他关节，无法满足约束时会恢复原姿态。
- **参数与控制 · 运行控制与载荷：** 在同一页下方实时调节执行器输入。配置了自动载荷规律的任务会显示公式和完整时长的加载曲线；自动控制的输入不能再手动调整。

工具栏可显示外载荷、惯量、质心和关节轴。外载荷显示用于说明施力位置和方向，不代表合力；绿色箭头表示施加的力，紫色弧线表示力矩，灰色箭头连接拖动作用点与鼠标目标。数值以数据曲线及单位为准。

## 网页计算、后台重算与实验导出

开始仿真后自动进入“数据”页。曲线按物理量和单位分组，勾选框控制显示；悬停时所有图表联动读取同一时刻。单击任意图表固定虚线与读数，移开鼠标后仍保留；再次单击任意图表解除固定，恢复跟随鼠标。Shift＋滚轮缩放时间轴，双击恢复全程。

每张图表右上角的 ↑／↓ 可上下调整位置；顺序按任务保存在当前浏览器，刷新或重新应用参数后保留，不改变计算结果和 CSV 数据。清空数据或切换任务会清除固定时刻。

### 两边都是 MuJoCo，为什么还要分两种？

网页端使用浏览器中的官方 MuJoCo WebAssembly 运行时计算物理运动，通过 WebGL 显示三维场景，不是用动画近似代替物理计算。后台使用 Python 的 `mujoco` 包调用本机原生引擎，不需要另外打开 MuJoCo 的 simulate 图形程序。

| 比较项 | 网页端计算 | 后台原生计算 |
| --- | --- | --- |
| 主要用途 | 交互调节、观察运动和曲线 | 重算核对、保存结果及实验条件 |
| 是否显示动画 | 是 | 重算不依赖动画刷新，页面显示进度 |
| 引擎版本 | MuJoCo 3.13.0 WASM | MuJoCo 3.13.0 原生库 |
| 导出时是否重新计算 | 导出网页数据时不再计算 | 按同一次实验的记录重新计算 |
| 是否自动更准确 | 精度取决于建模与求解设置 | 不因后台运行就自动更准确 |

两端的模型、初始状态、步长、求解器设置和输入一致时，结果应在数值误差范围内一致。帧率低可能让网页实验跑得慢、动画不流畅，不能据此判断物理结果更粗糙。后台通常能减少绘图开销；运行速度、采样频率和物理精度不能混为一谈。

精度主要受模型简化、质量／惯量、约束与接触、时间步长和求解器影响。需要更细时间步时，先改设置并重新完成网页仿真，再按新条件重算。不要只缩小后台步长后，把两次不同条件的实验混在一起比较。官方说明见[计算与仿真](https://mujoco.readthedocs.io/en/stable/programming/simulation.html)和[计算原理](https://mujoco.readthedocs.io/en/stable/computation/index.html)。

### 正确流程

1. 选择任务，修改模型参数、时长及步长并应用。
2. 用关节滑块或数值设置转角／位置，按需拖动调整姿态；松开后得到实际起点。姿态准备阶段不计时，准备后的速度归零。
3. 从 t=0 开始，运行到设定时长。可以暂停、继续；运行中的执行器调节会按仿真步记录。
4. 完成后点击“导出本次实验”，选择直接导出网页 CSV，或“后台重算并下载 CSV”。后台不会拿结束姿态当作起点。
5. 后台保存结果与实验条件，保留网页曲线并检查数值差异。以后可在“已保存的实验”下载该次后台 CSV。

例如，先把关节调到 60°，再拖动机构形成最终姿态 A，随后开始实验。网页和后台都从实际姿态 A 开始；若拖动改变了关节角，采用实际最终关节位置。仿真到终点姿态 B 后导出，后台仍从 A 起跑。若 t=1 s 调整了执行器，重算也在对应仿真步应用这个变化。

### 哪些条件会被保留？

- 当次实际应用的模型参数、时长与物理步长。
- 起始完整关节／自由刚体姿态、速度和积分所需内部状态，包括执行器状态、约束启用状态及求解热启动数据。
- 运行中手动执行器输入的变化及其仿真步。`loads.yaml` 的时间函数和反馈规律仍按相同规则重新计算。
- 网页实际采样时刻，后台在对应物理步输出，便于逐点核对。
- 模型、资源、观测和载荷的校验标识。文件已变更时拒绝把旧实验套到新模型上重算。

保存的是这次实验的条件，不是导出时界面的最新输入。完成后仅改变执行器，不会改写已完成记录；要研究新控制条件请重新开始。修改参数、时长、步长、关节姿态或再次拖动后，应重新完成网页实验。“重新开始”沿用已完成实验的起始姿态；“重置”恢复任务定义的初始状态。“清空”清除曲线并回到本次起点，避免把半段数据当作完整实验导出。

网页实验记录保留在当前页面，刷新前请导出；对话历史的保存不等同于实验状态保存。拖动用于准备起点，鼠标拖动路径不属于实验时间。运行中再次拖动会结束当前记录并准备新实验，当前功能不会把鼠标施力路径作为实验载荷重放。

### 后台保存哪些文件？

`tasks/<task_id>/results/run_*/` 下保存 CSV、曲线 JSON、单位、摘要，以及本次重算条件的 `experiment.json`。重新运行仍需对应的模型及资源；模型版本不匹配时，应先重新完成网页实验。

当前按钮一次重算一组实验，原“批量计算”名称不代表自动扫描多组参数。真正的参数扫描可以另外编写受控 Python 实验脚本。

### 两端有差异怎么办？

系统按每个数值的绝对误差与相对误差比较采样结果，当前容差为 `1e-8 + 1e-6 × max(|网页值|, |后台值|)`。这是复算一致性检查，不是力学正确性证明。

不同编译平台可能存在微小浮点差异，接触、碰撞或敏感系统可能放大差异，不能保证逐位相同。超出容差时先核对模型、实际初态、载荷、步长和求解设置，必要时缩短工况并做步长收敛分析；不要直接认定后台结果必然更准确。

### 计算规模与限制

计算过程中可查看进度或取消。网页仿真、加载曲线预计算和后台计算单次最多 1000000 步；后台另限 2000000 个观测数值、3600 秒仿真时间和 60 秒实际计算时间。步数上限提高不改变数据量和超时限制；规模过大时缩短时长、减少观测量或适当增大步长。网页实验采用有上限的采样记录，后台重算沿用该采样计划；直接调用后台的完整逐步输出仍受观测数值总量约束。若模型不稳定，应检查参数并减小步长。AI 生成任务仍限最高 60 秒仿真时长，最小步长与网页统一为 0.00001 秒，可在此时长内达到百万步。

## 模型预览

点击顶部“模型预览”，可从模型库选择模型及入口，也可拖入一个 MuJoCo XML 文件。模型库优先选 `scene.xml` 等场景入口，并保留配套网格、纹理和 XML 文件。

预览支持视角操作、关节姿态调整、拖动和运行/暂停；不采集任务曲线、不保存实验结果。点击“退出预览”或按 Esc 返回实验台，原任务保持暂停。

库外 XML 如果依赖外部文件，单独拖入可能无法读取全部资源，需要将模型及依赖整理为完整任务。机器人模型未必带有平衡控制器，运行后倾倒不一定是软件故障。复杂模型运行较慢时，可关闭阴影、光照等显示效果。

## 让 AI 创建学习任务

需要从零编写 XML 时，可[下载默认 XML 模板（含灰色 logo）](/api/task-template)，模板已整合在现有的 `docs/task-package-spec.md` 中。让 AI 复制其中的默认 XML，并把 `assets/logos/logo-gray.png` 复制到任务的 `assets/logo-gray.png`，替换示例研究对象，保留地面中央的 logo，再补齐任务配置。网页中的 Logo 以低透明度水印呈现，隐约可见并融入地面。

向 AI 描述研究对象、简化假设、希望改变的参数和观察量，让它按项目的任务目录规则创建或修改学习任务。完成后在实验台刷新任务列表，再选择任务开展实验。

建模规范、载荷语法和开发说明保留在项目文件中，供 AI 或教师按需阅读。学生不需要先阅读这些技术文档。提示词示例和核对要点见[AI 使用与提示词](task-guide.md#ai-提问与提示词)。

## 常见问题

- **找不到 Python 或版本不支持：** 安装 64 位 Python，建议 Python 3.12，并重新打开启动脚本。
- **首次安装失败：** 查看窗口里的具体报错，确认网络能访问 Python 软件包源，然后重新运行 `setup.bat`。
- **迁移后原环境不能运行：** 不要复用其他电脑的 `.venv`。安装脚本会检查失效或位置变更的环境，必要时将旧环境改名备份并重建。
- **原生 MuJoCo 自检失败：** 按安装窗口中的报错检查依赖或运行库；安装未完成前无法进行批量计算。
- **网页没有自动打开：** 保留启动窗口，手动访问 <http://127.0.0.1:8000>；若打不开，先看窗口是否报错。
- **8000 端口被占用：** 若 VMAIL 已启动，直接打开已有页面；否则关闭占用该端口的程序后重试。
- **页面还是旧界面：** 重启后台后强制刷新浏览器。运行包必须包含最新 `app` 文件夹。
- **右键手势拦截平移：** 切换“平移”模式后用左键操作，或使用 Shift＋左键。
- **新任务没有出现：** 让 AI 检查任务是否登记到全局索引，再点击任务列表刷新按钮。
