# 网页计算、后台重算与实验导出

[项目首页](../README.md) · [学生使用手册](user-guide.md)

## 两边都是 MuJoCo，为什么还要分两种？

网页端使用浏览器中的官方 MuJoCo WebAssembly 运行时计算物理运动，通过 WebGL 显示三维场景，不是用动画近似代替物理计算。后台使用 Python 的 `mujoco` 包调用本机原生引擎，不需要另外打开 MuJoCo 的 simulate 图形程序。

| 比较项 | 网页端计算 | 后台原生计算 |
| --- | --- | --- |
| 主要用途 | 交互调节、观察运动和曲线 | 重算核对、保存结果及实验条件 |
| 是否显示动画 | 是 | 重算不依赖动画刷新，页面显示进度 |
| 引擎版本 | MuJoCo 3.13.0 WASM | MuJoCo 3.13.0 原生库 |
| 导出时是否重新计算 | 导出网页数据时不再计算 | 按同一次实验的记录重新计算 |
| 是否自动更准确 | 精度取决于建模与求解设置 | 不因后台运行就自动更准确 |

两端的模型、初始状态、步长、求解器设置和输入一致时，结果应在数值误差范围内一致。帧率低可能让网页实验跑得慢、动画不流畅，不能据此判断物理结果更粗糙。后台通常能减少绘图开销；运行速度、采样频率和物理精度不能混为一谈。

精度主要受模型简化、质量／惯量、约束与接触、时间步长和求解器影响。需要更细时间步时，先改设置并重新完成网页仿真，再按新条件重算。不要只缩小后台步长后，把两次不同条件的实验混在一起比较。官方说明见[计算与仿真](https://mujoco.readthedocs.io/en/stable/programming/simulation.html)和[计算原理](https://mujoco.readthedocs.io/en/stable/computation/index.html)。

## 正确流程

1. 选择任务，修改模型参数、时长及步长并应用。
2. 用关节滑块或数值设置转角／位置，按需拖动调整姿态；松开后得到实际起点。姿态准备阶段不计时，准备后的速度归零。
3. 从 t=0 开始，运行到设定时长。可以暂停、继续；运行中的执行器调节会按仿真步记录。
4. 完成后点击“导出本次实验”，选择直接导出网页 CSV，或“后台重算并下载 CSV”。后台不会拿结束姿态当作起点。
5. 后台保存结果与实验条件，保留网页曲线并检查数值差异。以后可在“已保存的实验”下载该次后台 CSV。

例如，先把关节调到 60°，再拖动机构形成最终姿态 A，随后开始实验。网页和后台都从实际姿态 A 开始；若拖动改变了关节角，采用实际最终关节位置。仿真到终点姿态 B 后导出，后台仍从 A 起跑。若 t=1 s 调整了执行器，重算也在对应仿真步应用这个变化。

## 哪些条件会被保留？

- 当次实际应用的模型参数、时长与物理步长。
- 起始完整关节／自由刚体姿态、速度和积分所需内部状态，包括执行器状态、约束启用状态及求解热启动数据。
- 运行中手动执行器输入的变化及其仿真步。`loads.yaml` 的时间函数和反馈规律仍按相同规则重新计算。
- 网页实际采样时刻，后台在对应物理步输出，便于逐点核对。
- 模型、资源、观测和载荷的校验标识。文件已变更时拒绝把旧实验套到新模型上重算。

保存的是这次实验的条件，不是导出时界面的最新输入。完成后仅改变执行器，不会改写已完成记录；要研究新控制条件请重新开始。修改参数、时长、步长、关节姿态或再次拖动后，应重新完成网页实验。“重新开始”沿用已完成实验的起始姿态；“重置”恢复任务定义的初始状态。“清空”清除曲线并回到本次起点，避免把半段数据当作完整实验导出。

网页实验记录保留在当前页面，刷新前请导出；对话历史的保存不等同于实验状态保存。拖动用于准备起点，鼠标拖动路径不属于实验时间。运行中再次拖动会结束当前记录并准备新实验，当前功能不会把鼠标施力路径作为实验载荷重放。

## 后台保存哪些文件？

`tasks/<task_id>/results/run_*/` 下保存 CSV、曲线 JSON、单位、摘要，以及本次重算条件的 `experiment.json`。重新运行仍需对应的模型及资源；模型版本不匹配时，应先重新完成网页实验。

当前按钮一次重算一组实验，原“批量计算”名称不代表自动扫描多组参数。真正的参数扫描可以另外编写受控 Python 实验脚本。

## 两端有差异怎么办？

系统按每个数值的绝对误差与相对误差比较采样结果，当前容差为 `1e-8 + 1e-6 × max(|网页值|, |后台值|)`。这是复算一致性检查，不是力学正确性证明。

不同编译平台可能存在微小浮点差异，接触、碰撞或敏感系统可能放大差异，不能保证逐位相同。超出容差时先核对模型、实际初态、载荷、步长和求解设置，必要时缩短工况并做步长收敛分析；不要直接认定后台结果必然更准确。
