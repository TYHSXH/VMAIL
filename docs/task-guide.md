# 任务创建指南：工作流、AI 提示词与 STL 建模

[项目首页](../README.md#文档导航) · [学生使用手册](user-guide.md) · [任务包规范与载荷参考](task-package-spec.md)

面向创建或修改学习任务的教师、学生与 AI。先明确力学问题，再选用网页助手或本地编辑器；配置字段与默认模板统一查阅任务包规范。

可直接点击实验台顶部“我是菜鸟·AI”，在“历史与连接”绑定自己的 DeepSeek API Key，通过自由对话创建任务。选中已有任务后，可以直接让助手读取、排查并修改同一个任务，不必换编号新建。文件在后台校验后自动保存；失败时继续对话修正，不需要单独点击生成和加入按钮。详细操作见[学生使用手册](user-guide.md#用-deepseek-对话创建任务)。网页创建支持基础几何体、标准载荷和单参数多目标 MJCF 联动，不执行脚本。

需要外部模型资源或复杂脚本时，用能读写本地文件的 AI 编程工具打开 VMAIL 项目文件夹，使用下方提示词。AI 负责生成任务文件，你负责明确问题、确认建模假设并判断结果是否合理。

## 任务创建流程

### 角色边界

**学生**

- 描述自己感兴趣的真实结构或课本模型。
- 说明想改变哪些参数。
- 说明想观察哪些运动量、力或力矩。
- 在网页中运行仿真、查看曲线、导出数据。

**AI coding 工具**

- 把真实对象简化成理论力学模型。
- 创建或修改 `tasks/` 下的学习任务包。
- 编写 MuJoCo MJCF 模型。
- 配置参数、观测量和网页展示。
- 根据网页报错修复任务包。

**VMAIL 网页实验台**

- 读取 `tasks/manifest.yaml`。
- 打开任务包。
- 展示可调参数。
- 在浏览器中运行 MuJoCo WASM，并显示三维运动视图和实时数据曲线。
- 调用本地 Python 后端执行需要完整保存数据的批量实验。
- 导出或保存 CSV、JSON 和摘要文件。

### 标准流程

1. 学生在 AI coding 工具中打开 VMAIL 项目。
2. 学生说：“我想新建一个学习任务，研究……”
3. AI 询问或推断建模对象、参数、观测量和初始条件。
4. AI 在 `tasks/` 下创建任务文件夹。
5. AI 更新 `tasks/manifest.yaml`。
6. 学生运行 `start.bat`。
7. 学生在网页中选择任务、修改参数、运行仿真。
8. 结果保存到该任务的 `results/` 文件夹。
9. 学生如果有新要求，回到 AI coding 工具继续修改任务。
10. 学生回到网页点击“刷新任务”，继续实验。

### 照片建模

学生可以把照片或草图交给 AI，但目标不是精确三维重建，而是完成理论力学意义上的简化建模。

例如：

```text
照片：自行车前叉
简化：车身质量块 + 车轮质量块 + 竖直滑动约束 + 弹簧阻尼
```

AI 应先说明：

- 哪些部件被视为刚体；
- 哪些连接被视为关节或约束；
- 哪些真实细节被忽略；
- 哪些参数可以改变；
- 哪些结果值得观察。

学生确认后，再创建任务包。

## AI 提问与提示词

### 提问前先说清什么

- **对象与问题：** 研究什么机构，想解释或比较什么现象；不要只说“帮我做一个模型”。
- **条件与参数：** 尺寸、质量、初始角度、约束、摩擦和单位。未知数可以先用估计值，但让 AI 标明。
- **载荷与控制：** 力或力矩的大小、作用点、方向、参考坐标系以及如何随时间变化。
- **输出与对照：** 希望观察哪个点或关节的位移、速度、加速度或受力，以及准备用什么理论公式核对。

### 创建任务的提示词

复制下面内容，替换方括号中的说明。不确定的条件可以让 AI 先解释并与你确认。

#### 粗略版提示词

```
请在当前 VMAIL 项目中创建一个理论力学学习任务。
先读取给你的文字和示意图，确定已知条件，明确我们需要研究的问题，选取合适的对象，进行运动分析和受力分析，列方程解方程，得到要求的量。
```

#### 详细版提示词

```text
请在当前 VMAIL 项目中创建一个理论力学学习任务。

确定研究对象：例如【曲柄滑块机构】
进行运动分析和受力分析：例如【自由度是XX，广义坐标是XX，受到力是XX，其中未知力是XX】
明确要求的量：例如【求滑块加速度】
已知条件及单位：【杆长、质量、连接方式、初始状态等】
要改变的参数及范围：【如曲柄角速度 1–5 rad/s】
载荷或控制：【如恒定转速驱动；若为外力，说明作用点、方向、坐标系和时间规律】
要观察的结果：【如滑块位移、速度、加速度，输出曲线和 CSV】
理论核对方法：【如机构运动学公式；不确定时请建议】

请先说明简化假设、自由度和单位；缺少必要条件时先问我。
先阅读 tasks/AGENTS.md 和 docs/task-package-spec.md；需要载荷时查阅其中的“任务载荷与控制规律”章节。
只在 tasks/ 下新建独立任务，登记 tasks/manifest.yaml，不为单个任务修改公共前后端。
如果需要新写或重写 XML，使用 docs/task-package-spec.md 中“默认 XML 模板”的代码，并把项目的 assets/logos/logo-gray.png 复制为任务内 assets/logo-gray.png；保留深色地面中央的灰色 logo，按模型尺度调整，不平铺；网页以低透明度水印呈现，使其隐约可见并融入地面。
参数提供中文名称、单位与范围，观测量对应实际模型；固定研究点用具名 site。
完成后运行 backend.validate_task 和完整默认时长的计算，检查数值稳定性。
在 notes.md 中写清假设和结果解读，并告诉我网页里应调什么参数、看什么曲线。
```

### 修改任务或报告错误

```text
请修改已有 VMAIL 任务：【任务 id 或名称】。
我希望改变：【具体改变、参数和单位】。
目前出现：【原始报错、复现步骤或异常现象】。
我期望：【应有的结果，可附课本公式或截图】。

请先阅读该任务文件和 tasks/AGENTS.md，说明原因后修改同一个任务。
保留与本次修改无关的配置和已有实验结果，不改公共系统代码。
修改后重新校验并计算完整时长，说明修复内容和网页操作方法。
```

给照片或草图时，先让 AI 识别部件、连接、约束和外力，提出简化模型并说明忽略了什么；确认后再生成任务。不要把外观相似当成物理模型正确。

### 使用 AI 时要核对什么

1. 看清假设：是否把柔性构件当成刚体，是否忽略摩擦，连接或驱动是否符合题意。
2. 核对单位与含义：度和弧度、力与力矩、执行器指令与实际受力不能混用；确认作用点和正方向。
3. 先跑简单工况：用已知公式、对称性、守恒关系或极限情况核对，再扩大参数范围。图形能动、曲线平滑不等于结果正确。
4. 参数改变后重新应用；比较实验时保持初始状态、步长和观察量一致。出现不稳定或异常值时保留报错，让 AI 检查原因。
5. 要求 AI 报告实际运行的校验和计算结果；“已生成文件”不代表已经验证。提交实验作业前，由你解释结果与模型的局限。

具体题目的物理说明在实验台“任务”页阅读。[返回学生使用手册](user-guide.md)。

## 复杂几何体与 STL／MJCF 建模

### 什么时候需要自己建立模型

AI 可以辅助分析、写 MJCF 和检查错误，但无法仅凭一张题图可靠恢复尺寸、装配关系和接触形状。MuJoCo 的 box、sphere、capsule、cylinder 等基础几何体适合理想化模型；若孔洞、楔面、槽道、非规则轮廓或真实接触面影响研究结论，学生可能需要自行建立 CAD／STL 模型，再由 AI 辅助编写 MJCF。不要为凑出动画而改变实际自由度或约束。

先判断研究是否真的依赖外形。如果只研究铰接刚体的运动学，简单显示几何体配合正确关节、质心和惯量常常足够；若涉及接触、滚动或碰撞，实际碰撞几何体必须表达相关轮廓。

网页 AI 新建任务只接收基础 MJCF 与标准载荷，不能上传／生成 STL 或执行 CAD 工具。网格模型请在本地编辑器中整理为完整任务；已有任务的网页修改可以保留其已有资源引用，但不能补充缺失的二进制文件。

### 学生与 AI 的分工

1. 学生列出尺寸、单位、零件、关节位置、自由度、接触面、材料或质量数据和简化假设。缺少决定结果的条件时先补全，不让 AI 猜测。
2. 学生用自己熟悉的 CAD 工具建模，每个独立运动的刚体分别导出三角网格，保留原始 CAD 文件以便修改。
3. 导出**二进制 STL**；MuJoCo 也支持 OBJ。STL 不记录单位，必须说明导出坐标是米还是毫米。毫米模型通过 `scale="0.001 0.001 0.001"` 转为米。`body`、`joint`、`site` 的位置仍应使用米，不会跟着 mesh scale 自动换算。
4. 将资源放到 `tasks/<task_id>/assets/`，路径使用任务内相对路径，保持大小写一致，不引用其他任务、桌面或绝对路径。尽量减少无关细节和面数。
5. 学生与 AI 共同编写 `model.xml`：定义刚体层级、关节轴、质量／惯量、接触、驱动和观测点，补齐六个任务文件并更新 `tasks/manifest.yaml`。新建时复用[默认灰色 logo 模板](task-package-spec.md#默认-xml-模板)。
6. 编译、预览、短时仿真，再比较理论、实验或极限工况。每次只改一类内容，保留能运行的版本。

STL 只提供表面三角形，不包含关节、载荷、密度、质量、惯量或控制器。装配 CAD 直接导出一个 STL，通常也不会保留可运动的装配关系。

### 视觉外形与碰撞形状

MuJoCo 普通 mesh 的碰撞检测使用网格的**凸包**。一个带孔或凹槽的 STL 可以正确显示，但其凸包可能把孔封住、把槽填满。提高三角形精度无法解决这个问题。参见 [MuJoCo mesh 官方说明](https://mujoco.readthedocs.io/en/stable/XMLreference.html#asset-mesh)。

通常将完整外形作为只显示的 geom（关闭接触），再用多个基础形状或经 CAD／离线工具分解得到的凸网格构成碰撞体。每个凸块单独注册为 mesh 和 geom，保留实际需要的孔隙。不要通过随意增加焊接约束、阻尼或穿透来掩盖接触建模错误。

下面片段应合并进已有默认模板，不是完整任务。示例假设 `part_mm.stl` 以毫米导出，零件沿 body 局部 X 轴长 0.20 m、宽 0.04 m、厚 0.02 m；碰撞盒尺寸和均匀矩形体惯量仅作写法示范，实际零件必须重新计算：

```xml
<asset>
  <!-- 保留模板中已有的 logo texture 与 material -->
  <mesh name="part_visual" file="assets/part_mm.stl"
        scale="0.001 0.001 0.001"/>
</asset>
<worldbody>
  <!-- 保留模板中已有的 floor -->
  <body name="part" pos="0 0 0.3">
    <joint name="part_hinge" type="hinge" pos="0 0 0" axis="0 1 0"/>
    <!-- 示例质心位于铰点右侧 0.1 m，惯量以质心主轴计算 -->
    <inertial pos="0.1 0 0" mass="1"
              diaginertia="0.0001666667 0.0033666667 0.0034666667"/>
    <geom name="part_appearance" type="mesh" mesh="part_visual"
          contype="0" conaffinity="0" mass="0" group="2"
          rgba="0.45 0.55 0.65 1"/>
    <!-- box size 是半尺寸；该碰撞盒不适用于真实有孔／槽的零件 -->
    <geom name="part_collision" type="box" pos="0.1 0 0"
          size="0.1 0.02 0.01" mass="0" rgba="0.4 0.5 0.6 0.15"/>
    <site name="tip" pos="0.2 0 0" size="0.005"/>
  </body>
</worldbody>
```

不要在同一 XML 重复粘贴两个顶层 asset／worldbody 块；将子元素分别合并。STL 的原点和朝向须与示例 body 坐标一致，实际情况可通过 geom 的 `pos`／`quat` 调整。这里显式设置了整个 body 的质量和惯量，视觉体／碰撞体不重复贡献质量。若使用自动推断，请检查每个 geom 的质量／密度，避免视觉与碰撞几何体重复计入；质量与惯量应来自测量、CAD 或明确的理论近似。

### 任务结构与验证

```text
tasks/my_mesh_task/
  task.yaml
  model.xml
  parameters.yaml
  observe.yaml
  ui.yaml
  notes.md
  assets/
    logo-gray.png
    part_mm.stl
    collision_01.stl      # 按需添加，多个凸块分别引用
  SOURCE.md              # 外部资源的作者、来源、许可与修改情况
  LICENSE                # 按需保留上游许可证
```

```powershell
.\.venv\Scripts\python.exe -m backend.validate_task my_mesh_task
```

校验通过后回到网页刷新任务列表。先在暂停状态核对朝向、尺寸、关节轴和质心；再小步长短时间试跑，检查穿透、接触、速度和加速度数量级，最后才做完整实验和参数比较。所有模型引用资源总量受本系统 128 MiB 限制；简单减小面数常能降低加载和运行负担。

可直接交给本地 AI 的提示词：

```text
请阅读 tasks/AGENTS.md 和 docs/task-guide.md。
我已将零件 STL 放入 tasks/my_mesh_task/assets/，尺寸单位为毫米。
零件原点、朝向、关节位置、质量与惯量分别为……。
研究重点是……，必须保留的接触面／孔槽是……。

和六个任务文件，保留默认灰色 logo 地面，登记索引并运行任务校验。
不要凭空编造二进制 STL、惯量或闭环约束；需要重新建 CAD 时请明确说明。
```

### 常见错误

| 问题 | 优先检查 |
| --- | --- |
| 零件大／小了 1000 倍 | STL 导出单位、mesh scale，以及关节／site 位置是否分别使用米 |
| 看得见孔却不能穿过 | 凸包碰撞；将相关凹形分解为多个凸碰撞体 |
| 出现 invalid header 或 STL 格式错误 | 是否误用了 ASCII STL；重新导出二进制 STL 或 OBJ |
| XML 能编译但运动明显不对 | 自由度、关节轴、质心惯量、驱动、接触和单位；编译成功不证明模型正确 |
| 任务缺少资源 | 复制整组 XML 与 assets，核对相对路径和大小写，禁止引用任务外文件 |
| 加载很慢或超限 | 减少面数、去掉无关资源、简化碰撞体，并核对 128 MiB 资源上限 |

学习入口：[官方建模教程](https://mujoco.readthedocs.io/en/stable/modeling.html)、[MJCF XML 参考](https://mujoco.readthedocs.io/en/stable/XMLreference.html)、[Python 接口](https://mujoco.readthedocs.io/en/stable/python.html)。本系统使用 MuJoCo 3.13.0，新特性请核对版本兼容性。外部 CAD、STL 和题图应保留来源及授权信息；AI 辅助生成的文件也需要学生检查并承担模型选择的责任。
